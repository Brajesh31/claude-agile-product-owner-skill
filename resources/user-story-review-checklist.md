# User Story Review Checklist

Use this checklist during refinement. A story is not ready merely because it has an “As a / I want / so that” sentence.

## INVEST review
- [ ] **Independent:** It can be planned without hidden dependencies, or dependencies are recorded.
- [ ] **Negotiable:** The implementation is not prescribed unnecessarily.
- [ ] **Valuable:** The user or business value is explicit.
- [ ] **Estimable:** The team has enough information to estimate it.
- [ ] **Small:** The story can realistically finish within the team's sprint.
- [ ] **Testable:** Acceptance criteria describe observable outcomes.

## Acceptance criteria
- [ ] Happy path is covered.
- [ ] Validation and permission rules are covered.
- [ ] Empty, boundary, and error states are covered where relevant.
- [ ] Accessibility and responsive behavior are considered.
- [ ] Performance or reliability expectations are measurable where needed.
- [ ] Data handling and privacy constraints are explicit.

## Scope and delivery
- [ ] The story has one primary outcome.
- [ ] Dependencies and external decisions are recorded.
- [ ] Design, API, and operational impacts are visible.
- [ ] Test data and environment needs are understood.
- [ ] The team agrees on the definition of done.
